# v0.7 Four Pillars Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.  
> **Product source of truth:** `ROADMAP.md` (v0.7 product pillars).  
> **Do not start coding without reading Global Constraints + Locked modular file structure.**

**Goal:** Ship **v0.7** with (1) full look-and-feel modernization of the whole shell, (2) channel tabs that behave like real tabs, (3) pilot intel as a first-class product surface, and (4) an opt-in LAN phone viewer that replicates the desktop feed display — without growing `signal_bridge_gui.py`.

**Architecture:** Keep Python 3.12 + Tkinter. Extend the existing `sb_ui` / `sb_*` modular layout. Pure domain and policy live in small non-Tk modules; Tk construction lives in focused `sb_ui/*` modules; networking for LAN lives in `sb_lan/` isolated from the UI thread. `signal_bridge_gui.py` is a **wiring shell only** (lifecycle, menus, queue drain, thin delegates).

**Tech Stack:** Python 3.12, Tkinter, pytest, stdlib HTTP/SSE for LAN (no heavy frameworks), existing `sb_contracts` / `sb_settings` / Intel History add-on.

## Global Constraints

### Product / runtime (from `docs/INVARIANTS.md` + ROADMAP)

- Tk UI thread must not block (no network, MT, disk walks, or SSE fan-out on the UI thread).
- Render path uses precomputed row/translation data only.
- LAN viewer is **opt-in**, LAN-only, read-only, tokenized URL; no tokens/logs/settings exposure.
- Portable ZIP stays lightweight; no admin rights; no Argos/Torch in default build.
- Do not start Tauri/v3 rewrite for 0.7.
- `APP_VERSION` stays **0.6** until the packaging cut that publishes 0.7 (bump only at ship).

### Modularity (mandatory — non-negotiable)

1. **One concern per file.** No grab-bag `utils.py` dumps.
2. **Size budget.** New/edited library modules: prefer **≤ ~300 lines**; **hard split before ~450 lines**. Packages use multiple small files. UI modules may run slightly larger only if pure layout with no policy (still split at ~500).
3. **GUI is wiring only.** `signal_bridge_gui.py` may:
   - import and call module APIs
   - create root window / menus / queue drain hooks
   - pass settings/state into modules  
   It must **not** gain new multi-screen layout trees, tab state machines, LAN servers, or pilot domain logic.
4. **Extract-before-extend.** If a task needs code still in the GUI file, **move it out in that task (or a prerequisite)** before changing behavior.
5. **Dependency direction (never reverse):**
   ```text
   sb_contracts / pure policy
        ↑
   sb_channels, sb_lan (logic), sb_pilot (domain), sb_theme tokens
        ↑
   sb_ui/* (Tk builders — no business algorithms)
        ↑
   signal_bridge_gui.py (wiring only)
   ```
   Library modules **must not** import `signal_bridge_gui`.
6. **Tests live with the module.** `tests/test_<area>.py` imports modules directly. Avoid full `SignalBridgeGui` unless testing wiring.
7. **No drive-by refactors** of ESI/catalog/TranslationCache full classes unless a task’s extract slice requires it.
8. **One logical commit per Task** (message given). Prefer: test → extract → behavior → wire.
9. After every task:
   ```powershell
   python -X utf8 -m py_compile <touched files>
   python -X utf8 scripts/check-fixtures.py
   python -m pytest tests/ -q
   ```
10. User-facing closes: update `CHANGELOG.md` Unreleased; keep `ISSUES.md` honest.
11. Visual tasks require **before/after** notes (screenshot paths under `docs/images/` or agent notes).

### Visual design (pillar 1)

- **Approved theme: Void Tactical (Mockup A)** — see `docs/superpowers/specs/2026-07-10-v0.7-void-tactical-theme.md` and `docs/images/signal-bridge-v0.7-theme-mockup-a.png`.

# --- LAN viewer (Pillar 4) ---
sb_lan/
  __init__.py
  config.py                    # enable, port, token, bind host policy
  server.py                    # stdlib ThreadingHTTPServer / SSE (background thread)
  feed_buffer.py               # bounded ring of serializable feed rows
  theme_css.py                 # theme tokens → CSS variables / classes
  serialize.py                 # RenderRow / visible line → JSON for browser
  security.py                  # token check, no path traversal, deny list

sb_ui/lan_page.py              # Settings page: enable, URL, QR, copy, stop, client count
# Optional: sb_ui/qr.py tiny QR helper or pure lib if stdlib-only QR is too large —

  styles.css                   # base; variables injected from theme

# --- Existing modules (touch only if extract-before-extend) ---
sb_contracts/render_row.py     # fill spans if LAN needs semantic styling
sb_channels.py                 # catalog; tabs consume channel ids
sb_settings.py                 # new keys for LAN + any tab prefs
signal_bridge_gui.py           # wiring only; line count should not grow net

## Wiring rules for `signal_bridge_gui.py`

```python
from sb_tabs import state_from_settings, select_tab

from sb_ui.pilot import open_pilot_card

```

Forbidden:
- New 100+ line methods that build complex UI trees (put in `sb_ui/…`)
- Inline LAN HTTP handlers
- Inline tab order algorithms
- New pilot zKill HTML layout in the GUI file

**Net goal:** `signal_bridge_gui.py` line count **flat or down** by end of 0.7 (extracts ≥ new wires).
